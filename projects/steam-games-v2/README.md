# Steam Games V2

价格、好评与在线热度之间的关系，能跨过类型与发行年龄的差异吗？

## 数据集简介

这是一个以 appid 为连接键的 Steam 游戏多来源快照：主表包含商店字段和玩家参与指标，另有 SteamSpy 估计以及 Wikidata 元数据。它用于观察数字游戏市场中的价格、评价、在线人数、发行时间和多标签类型结构，不是 Valve 的销售账本。

**用途：** 用于研究价格、好评率、快照 CCU、发行年龄和游戏类型之间的关系，并展示长尾集中、多标签共现和多表连接的影响。

**观测单位：** 主分析一行代表归并后的唯一 appid；genres/categories 是多标签字段，CCU、评价和价格来自不同时间口径，不能把它们直接解释成因果链。

**来源说明：** 本地文件是 Kaggle 发布的 Steam 数据快照，结合 Steam/SteamSpy/Wikidata 表；SteamSpy 官方说明其数据来自多日样本且对新游戏不可靠，因此这里把 CCU 当作快照指标。

## 复现

从仓库根目录运行 `python3 projects/steam-games-v2/eda.py`，再运行 `python3 scripts/build_sites.py`。依赖见根目录 requirements.txt。

## 分析过程

1. 逐表检查 appid 重复与冲突；主表按完整度→评价数→原始顺序归并，无 timestamp 不假称最新。
2. Wikidata 分类属性按键聚合，所有 merge 强制 one_to_one，验证行数与唯一性。
3. 保留美分原值并派生 USD；混合日期格式解析，记录失败数。
4. 评价关系要求 n_reviews≥50，零价格/零 CCU 均保留。
5. 比较总体、价格分层、类型 × 年份内秩相关。
6. 计算 CCU Lorenz 曲线和多标签共现 lift，限制低支持组合。

## 实际计算的结论

### CCU 极度集中，总体均值很容易误导

按唯一 appid 统计，CCU 最高的 1%（227 个游戏）贡献 82.1% 的快照 CCU；11,255 个游戏 CCU=0。价格图使用 symlog，保留零价格、零 CCU，不用 log 轴无声删除长尾。

### 好评率不等于热度

至少 50 条评价的 17,773 个游戏中，好评率与 CCU 的 Spearman ρ=0.332。对秩值按首个类型标签 × 发行年去均值后为 0.314；两者差异提示类型与年龄构成值得关注，但未消除营销和存活偏差。

### 多标签组合需要同时看数量与 lift

网络保留共同出现≥100 次的前 35 对类型。线宽表示共同游戏数，悬停显示 lift=联合概率/(边际概率乘积)；高频类别不一定有最强的超预期共现。

### 多来源连接必须保留审计记录

主表 23,100 行归并为 22,608 个 appid；3 个重复键含冲突内容。采用完整度、评价数和原始顺序选择，不能称为“最新记录”。Wikidata 匹配率 93.9%，SteamSpy CCU 不一致 0 行；日期成功解析 22,492 行。

## 局限

- 快照 CCU、累计评价、当前促销价格的时间口径不同，不推断价格导致流行。
- 零价格可能与免费发行、不可购买或商店状态有关，不将零价格等同于 free-to-play。
- 首个类型标签只是粗控制；发行年龄混杂仍可能存在。
- 重复冲突只能按明确规则选择，没有可靠更新时间可确定真值。
