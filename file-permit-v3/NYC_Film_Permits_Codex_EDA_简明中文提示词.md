# Codex 任务：从零开始完成 NYC Film Permits 数据集的 EDA

我正在完成一门数据分析与可视化课程的小组项目。请用 Python 帮我从头完成纽约市 Film Permits 数据集的探索性数据分析（EDA）。这是一份课堂项目，不需要企业级工程设计，也不需要复杂的预测模型。重点是：分析过程清楚、代码容易理解、图表好看、结论有数据支持。

## 唯一的已知数据来源

数据集官网（请先阅读网页介绍与数据字段说明）：
https://data.cityofnewyork.us/City-Government/Film-Permits/tg4x-b46p/about_data

请在当前项目文件夹中寻找 Film Permits 的 CSV 文件并读取。如果找不到，请说明如何从上述官方网站下载，而不是凭空创建数据。

**重要：从零开始探索数据。** 在真正读入文件前，不要假设 CSV 有多少行、哪些列、哪些值缺失、涵盖哪些年份，也不要预先写死特定列名或统计结果。网页只是了解数据背景的来源；实际字段、数据量、时间范围和分析发现，都要以实际读取的 CSV 为准。如网页说明与本地文件不同，请指出差异。

## 你要完成的工作

### 第 1 步：认识数据

使用 pandas 读取 CSV，打印并简单解释：
- 行数、列数、列名、前几行样例；
- 每列的数据类型、缺失值数量和比例；
- 重复行情况，以及合适情况下的唯一标识符重复情况；
- 分类变量有哪些、常见取值是什么；
- 如果有日期字段，实际日期范围是什么。

先根据检查结果，用简短中文说明：这个数据集记录的是什么？一条记录代表什么？哪些字段适合做分析？有什么明显的数据质量问题？

### 第 2 步：清洗数据

根据真实检查结果进行必要的清洗，不要机械地删除所有缺失值。可考虑：
- 处理完全重复记录；
- 去掉文本字段多余空格，统一明显不一致的写法；
- 将实际存在的日期列转换为 datetime；
- 检查不合理的日期先后关系、异常类别或明显错误值；
- 按不同分析需求决定是否排除缺失记录。

对于每一种清洗操作，请说明“为什么这样做”“影响多少条记录”。不要随意把看起来很大的数值当作异常值删除。保留原始 CSV，另存清洗后的数据文件。

### 第 3 步：构造方便分析的新变量

根据实际存在的字段，适当提取有用信息。例如，**如果有可用的开始日期**，可以提取年份、月份、星期、小时、是否周末；**如果同时有开始和结束日期**，可以计算两者的时间间隔；**如果有录入日期**，可以研究记录提前量。

这些只是候选项，不是对列名或数据结构的预设。实际没有相应字段时，跳过并解释。时间跨度不一定等于真实工作时长，解释时要准确。

### 第 4 步：开展 EDA 并制作图表

请围绕下面几个自然的问题进行分析，前提是实际字段支持：

1. **时间变化：** 活动/许可证数量随年份和月份如何变化？是否存在季节性？如果最新一年不完整，不要直接拿它与完整年度比较。
2. **类别构成：** 哪些制作类别或活动类型最常见？占比多少？
3. **地理分布：** 哪些行政区或地区的记录较多？不同地区的类别构成是否不同？
4. **时间习惯：** 活动一般在哪些星期、时段开始？工作日和周末是否有差别？
5. **持续时间：** 如果可计算时间跨度，不同类别之间有何差异？是否存在异常长或短的记录？
6. **可选拓展：** 如果数据支持，还可以研究记录提前量，或者寻找一个有趣的交叉分析结果。

先画出基本的单变量图，再做不同变量的交叉比较。推荐使用折线图、柱状图、热力图、直方图和箱线图；只有数据和时间允许时才尝试地图，不必为了炫技做复杂地图。

请根据真实数据和图表效果决定具体画哪些图，不需要机械地凑数量。目标是筛选约 **8～10 张适合课堂展示的高质量图表**，每张图有英文标题、坐标轴标签和必要的单位；代码注释和分析说明使用中文。避免标签重叠、过密、图例遮挡等问题。尽量使用 pandas、matplotlib、seaborn；若确实必要再增加别的包。

**注意统计口径：** 数据可能是一条许可证一条记录，而不是一部影视作品一条记录。只有确认记录含义后才能命名统计指标。多地区字段如果含多个值，不能在拆分计数后错误地把数量当作互不重复的许可证总数。

### 第 5 步：解释发现

每个重要图表下面都用简洁中文回答：
- 这张图展示什么？
- 最明显的 1～2 个发现是什么？（写出必要的数字）
- 这个发现可能意味着什么？
- 有哪些不能直接从数据推断的事情？

请区分“数据证明的事实”和“可能的解释”。不要根据图表直接推断行业收入、作品数量或事件成因。

最后概括 3～5 条最有价值的结论，并说明数据限制。

## 实现形式与交付

- 以 **Jupyter Notebook** 为主要成果，按“数据认识 → 清洗 → 特征 → 探索分析 → 结论”的顺序编排。
- 每部分包含容易读懂的 Python 代码、Markdown 中文说明和对应输出。
- 尽可能保证从上到下运行全部单元格能成功执行。不要使用绝对路径；尽量使用相对路径。
- 保存清洗后的 CSV、筛选出的最终图表 PNG，以及一份简短的中文 `README.md`，介绍如何安装依赖、运行 Notebook、查看结果。
- 不需要搭建 Web App、数据库、复杂的多模块架构、自动化流水线或单元测试框架。
- 代码应适合有 Python 基础的学生阅读；不必过度封装。能用简单代码解决的，不要引入复杂抽象。
