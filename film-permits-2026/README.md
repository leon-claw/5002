# 纽约电影许可：探索性数据分析与 D3 可视化

本项目以用户提供的 `Film_Permits_20260930.csv` 为唯一统计输入。它与仓库中先前的 2011–2015 历史镜像不同，不能混用。网页用 D3.js v7 绘制六张交互图，Node.js 原生 HTTP 服务提供离线页面和已计算的汇总 JSON。

## 运行

环境：Node.js 18+；重跑 EDA 时需要 Python 3.10+、pandas、scipy（仓库根目录 `requirements.txt`）。

```bash
cd film-permits-2026
python3 analyze.py   # 可选：从原始 CSV 重算 public/data/analysis.json
npm start
```

浏览器打开 `http://127.0.0.1:3000/`。可用 `PORT=其他端口 npm start` 指定端口。D3 已在 `public/vendor/`，页面可在无外网环境下显示图表；在线字体不可用时会使用系统中文字体。`npm test` 检查服务、图表资源和关键汇总口径。

## 数据定义与质量

纽约市官方 [About Data](https://data.cityofnewyork.us/City-Government/Film-Permits/tg4x-b46p/about_data) 标注提供方为 Mayor’s Office of Media and Entertainment，`EventID` 是事件编号，`Category` 是申请人选择的制作类别，`Borough` 是当日活动的第一个行政区。官方将 `EnteredOn` 定义为向 MOME 提交许可申请的日期。因此“一行 = 一条许可事件”，不等于一部作品或实际拍摄一次。

| 检查 | 结果与处理 |
|---|---|
| 原始文件 | 19,420 行、14 列；EventID 全部唯一；不覆盖源文件 |
| 明显错位 | 8 行 Borough 列读到 EventType 文本，其他字段同步错位；主体分析剔除 |
| 主体样本 | 19,412 行 |
| 日期缺失 | StartDateTime 387；EndDateTime 165；EnteredOn 2,055（均在主体样本内） |
| 跨度 | 18,861 条有完整起止时间，其中 17 条负值；分位数仅用非负值，287 条超过 7 天仍保留 |
| 提前量 | 17,015 条有完整提交与开始时间，其中 3 条负值；分位数仅用非负值 |

日期以源文件中的美国 12 小时格式解析；不补零、不推断缺失。年度比较只用开始时间可解析的 2023–2025 三个完整年份。2026 年在本地文件中只有 1 条 7 月开始的事件，不能作为完整年度或月份比较。

## EDA 发现

1. **时间**：2024 年 6,278 条，2025 年 5,491 条，下降 12.5%。这是许可事件数量变化，不是作品数量变化。
2. **类型与空间**：全部许可中曼哈顿占 50.7%；只看 Shooting Permit 是 45.2%。Theater 类别的曼哈顿占比为 72.5%。类别与首个行政区的 Cramér’s V 为 0.175；限制为 Shooting Permit 后为 0.134。描述性关联不能解释因果，重复申请也使独立观测假设不成立。
3. **运营节奏**：完整且非负的申请提前量有 17,012 条，中位数 5.5 天。计划起止跨度中位数为 15.0 小时；这两个数字都不是审批处理时间或实际拍摄工时。
4. **周内差异**：有有效开始时间的剧场类事件中，周末占 27.6%，电视类为 7.0%；申请提前量中位数分别为 9.7 天与 4.9 天。这是类别对应活动的排期描述，不是偏好或机制的因果解释。

## 解释边界与复现结构

`ParkingHeld` 是预留停车地点文字，不是可验证坐标；`Borough` 仅是第一个活动区。CSV 没有可靠的作品或公司标识，不能去重到项目级。分类 × 行政区的统计只描述本文件的共同分布，不代表人口或面积标准化后的拍摄强度。申请时间缺失约一成，提前量结论只适用于完整记录。官方数据有自身更新周期，本报告所有数字固定于所附 CSV。

- `data/Film_Permits_20260930.csv`：只读原始输入。
- `analyze.py`：全量计算与质量检查。
- `public/data/analysis.json`：图表和页面可核验的汇总结果。
- `public/app.js`：D3.js 图表与交互。
- `server.js`：仅提供 `public/` 内文件的 Node.js 服务。
